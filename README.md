## Git 本地工作流

本仓库采用**纯本地 Git** 管理，无需联网、无需远程账号。

### 常用命令

```bash
# 查看当前状态
git status

# 查看提交历史
git log --oneline

# 存档当前改动
git commit -am "feat: 说明做了什么"
```

### 代码被改崩了怎么办

**情况一：改了但还没 commit** —— 丢弃改动，回到最近一次存档：

```bash
git checkout -- .
```

**情况二：已经 commit 了，想退回更早的版本** —— 先查编号，再回退：

```bash
# 1. 列出所有存档点，复制目标行开头的编号（如 a3f9c21）
git log --oneline

# 2. 回退到该版本
git checkout a3f9c21 -- .
```

### 提交信息规范

采用约定式提交（Conventional Commits）：

| 前缀 | 含义 | 示例 |
| :--- | :--- | :--- |
| `feat` | 新增功能 | `feat: complete pendulum MVP` |
| `fix` | 修复缺陷 | `fix: resolve reset button runtime error` |
| `docs` | 文档变更 | `docs: update week05 reflection` |
| `refactor` | 重构（不改功能） | `refactor: extract physics module` |
| `chore` | 杂项（配置、依赖） | `chore: init experiment workspace` |

## 实验方法论：四段式意图表达

本课程所有实验均采用统一的四段式 Prompt 结构指挥 AI 完成开发：

| 段落 | 作用 |
| :--- | :--- |
| **【角色】** | 告诉 AI 它是谁，决定它调用哪套知识体系 |
| **【目标】** | 一句话说清要交付什么 |
| **【约束】** | 划定边界，防止 AI 自由发挥偏离需求 |
| **【验收标准】** | 定义"什么叫做好了"，AI 会据此自检 |

核心原则：**人类负责意图设计与验收，AI 负责实现细节。**
