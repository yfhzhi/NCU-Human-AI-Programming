## 三、技术实现要点

### 3.1 物理模型

单摆的运动方程：

```
θ″ = −(g / L)·sinθ − c·θ′
```

- `g` 单位 m/s²，画面上 1 米 = 100 像素，因此 `g` 参与运算时乘以 `PX_PER_M`；
- 采用**四阶龙格-库塔（RK4）**积分，固定步长 1/240 s，配合累加器让物理步进与屏幕刷新率解耦；
- 使用 RK4 而不是欧拉法，是因为欧拉法在大角度、长摆长下会持续注入能量，摆幅越摆越大，20 秒后肉眼可见。

### 3.2 可调参数

| 参数 | 范围 | 步长 | 说明 |
| :--- | :--- | :--- | :--- |
| 摆长 L | 100 ~ 350 px | 1 px | 初始 200 px |
| 重力 g | 0 ~ 25 m/s² | 0.1 | 初始 9.8（地球） |
| 阻尼系数 c | 0 ~ 0.010 | 0.0005 | 初始 0 |

面板顶部另有**天体场景**胶囊按钮（地球 / 月球 / 木星 / 失重），点击后重力在约 0.3 秒内平滑过渡到目标值，同时滑块与数值标签实时跟随。

### 3.3 两处主动偏离课件的设计决定

这两处不是"随手改的"，而是我在验收时发现按原参数做出来的东西**在物理上说不通**，主动改的：

1. **重力滑块下界从 1 改为 0。**
   进阶挑战 B 要求"失重太空 g = 0"，但课件给的重力滑块范围是 1 ~ 25。如果照抄，点"太空"按钮时 g 会被滑块钳在 1，屏幕上表现成"月球"，功能名不副实。所以我把下界放开到 0，并补了一行提示语（"失重：没有回复力，摆球保持当前运动状态"），避免用户以为程序卡死。

2. **阻尼系数做了 120 倍的视觉映射。**
   课件给的阻尼范围是 0.000 ~ 0.010，若直接当作角速度阻尼项系数，最大阻尼下振幅衰减时间常数约 100 秒 —— 拖动滑块到最大，肉眼几乎看不出区别，"实时响应"的验收点就成了空话。因此代码里加了 `DAMPING_K = 120`，把 0.000 ~ 0.010 映射到肉眼可辨的衰减区间。这是**取舍**，不是 bug：物理形式没变，只是量纲映射为交互体验服务，代码里有注释说明。

### 3.4 其他工程细节

- Canvas 按 `devicePixelRatio` 缩放（上限 2 倍），高分屏不糊；
- 窄屏（≤ 760px）时面板变为底部抽屉，摆长按可用高度整体缩放，**视觉长度与物理长度同步缩放**，保证周期读数不跟画面打架；
- `localStorage` 记住参数，刷新后恢复；读取时逐项做类型与范围校验，脏数据不会把页面带崩；
- 无动画库、无字体外链，断网可用。

## 四、人机协同三反思

### 反思一 · 意图定义：把"我要一个单摆"翻译成可验收的约束

第一次下发的 Prompt 我做了一个判断：**不描述界面长什么样，只描述边界和验收标准。**

"做一个单摆模拟器"这句话对 AI 来说是开放的，它完全可以给我一个用 Three.js 做的 3D 单摆、或者一个依赖 CDN 的版本 —— 技术上都能跑，但一断网就白屏，而且我根本改不动。所以我在【技术约束】里写死了三条：单文件 `index.html`、纯原生 Canvas 不引外部库、`requestAnimationFrame` 驱动。这三条的作用不是"限制 AI"，而是**把"什么叫做好了"提前定义清楚**，让我在它交付时有一个客观的尺子，而不是凭感觉说"好像不太对"。

第二条体会是：**约束必须写到"路径"这一级。** 任务一结束时，我的仓库里已经有了一层 `week05_pendulum_sim/`，但任务二的 Prompt 我一开始只写了"在当前工作区创建 index.html"。AI 很听话地把它生成在了仓库**根目录** —— 它没有做错，它只是按字面执行。是我自己没把"无菌工作区"这个概念翻译成文件系统里的一个确定路径。第二轮我把约束改成"文件必须落在 `week05_pendulum_sim/index.html`"，问题立刻消失。

这件事让我理解了"意图"和"指令"的区别：意图在我脑子里，指令才是 AI 能看见的东西。**没有落进指令的意图，等于不存在。**

### 反思二 · 排错自愈：从一句红字到根因

这是本周我收获最大的一段。

**① 现象。** 第三轮加完滑块和按钮，页面打开正常、摆球正常摆动、三个滑块拖动也正常。但点"重置摆动"，摆球当场停住不动，控制台刷出一行红字。

**② 证据。** 按课件要求 F12 打开 Console，抓到的完整堆栈是：

```
Uncaught ReferenceError: resetAnimation is not defined
    at HTMLButtonElement.onclick (index.html:154)
```

**③ 读法。** 这行字里有三条信息，我当时是一条一条拆的：

- `ReferenceError` 而不是 `TypeError`：说明**根本没找到这个名字**，而不是"找到了但不是函数"。所以问题不在函数内部，函数压根没被调用起来。
- `at HTMLButtonElement.onclick`：报错位置是**元素的内联事件属性**，不是我的 `<script>` 里的某一行。
- `index.html:154`：正好是那个按钮所在的 HTML 行。

三条信息合起来，指向的结论很明确：**HTML 在喊一个 JS 里并不存在的名字。**

**④ 根因。** 翻代码发现，JS 里那个函数叫 `resetPendulum`。也就是说 AI 在第二版重构时把函数名从 `resetAnimation` 改成了语义更准的 `resetPendulum`，但 HTML 里 `onclick="resetAnimation()"` 这个字符串没人去改。**一次纯粹的命名漂移** —— 改的人以为改全了，用的人以为没改。

**⑤ 修复。** 我没有选择"补一个叫 `resetAnimation` 的空函数"这种糊弄式修法，也没有让 AI 把整个文件重写一遍。我让它做两件事：

1. 删掉 HTML 里的内联 `onclick` 属性；
2. 在 JS 里用 `addEventListener('click', resetPendulum)` 显式绑定。

理由：内联属性把函数名当**字符串**存着，改名时没有任何工具会提醒你；`addEventListener` 传的是**引用**，函数一改名，编辑器立刻标红。**修的是这一类问题的发生条件，不是这一个 bug。**

**⑥ 验证。** 刷新后控制台干净，重置按钮恢复正常。为了不再靠"我点一下试试"来确认，我让 AI 写了一个 Node 冒烟测试 `test/smoke_test.js`，用最小 DOM 桩把页面脚本跑起来，其中一条断言就是"重置按钮必须存在点击处理器"。这条断言恰好就是原 bug 的形态 —— 如果哪天再出现命名漂移，测试会直接失败，而不是等我上课演示时才发现。

**⑦ 对照。** 如果当时我给 AI 的反馈是"重置按钮坏了，重写一下"，它大概率会重写整个文件：新代码可能能跑，但我既不知道原来为什么坏、也不知道新代码有没有引入别的问题，而且**根因（内联字符串绑定）仍然躺在那里**，下次改别的按钮还会再犯一次。相比之下，"现象 + 完整堆栈 + 具体行号"这套证据，让 AI 一次就定位到了作用域和绑定方式，修复只动了 5 行。

**结论：报错不是障碍，是免费的诊断报告。人的工作不是消除红字，而是把红字翻译成根因。**

### 反思三 · 主体协同：AI 的手速与人的判断力

这次实验里，代码行数大约 90% 是 AI 写的 —— Canvas 的绘制样板、DPR 适配、`localStorage` 序列化这些"我知道要做什么但懒得敲"的部分，它几秒钟就给完了。但整个过程里，有四件事是它替不了的，而且每一件都真实地拦下过一个错误：

**第一，判断"物理对不对"。** AI 第一版用的是最简单的欧拉积分，代码能跑、摆球会动、看起来完全正常。但我盯着看了一分钟发现摆幅在**变大** —— 一个无阻尼单摆的机械能应该守恒，它却在给自己充电。这不是代码错，是数值方法错。要求换成 RK4 之后才稳定。AI 保证的是"程序能运行"，能不能保证"程序描述的世界是对的"，取决于人有没有那套判断标准。

**第二，追问语义。** 失重场景 `g = 0` 和滑块的 `min = 1` 冲突时，AI 的默认行为是把 `g` 安静地钳到 1 —— 从"程序不报错"的角度看，它做得很对；但从"我要一个失重场景"的角度看，它交付了一个假货。**AI 的优化目标是消除异常，人的优化目标是让结果有意义。** 这两者在边界条件下经常打架，而只有人能发现自己在被骗。

**第三，定义审美与可用性的下限。** 深色背景 `#1a1a24`、发光摆球、拖尾、周期读数、FPS —— 这些没有一条是"能不能跑"的必要条件，但它们决定了这个东西是"作业"还是"工具"。AI 不会主动给自己加标准，标准得人给。

**第四，承担验收责任。** 它说"已完成、0 报错"的时候，页面确实没报错 —— 因为**它从没点过那个按钮**。静态看代码永远看不出"点了才会炸"的错。真正把功能走一遍、把边界值拖到底、把窗口拉到手机尺寸，这些动作只能人做，也必须人负责。

所以我对"人机协同"的理解是：**AI 把手速借给了我，但它不承担后果。** 意图、标准、验收、以及出错之后"这是谁的责任"—— 这四件事构成了人在这个闭环里不可替代的位置。如果全交给 AI，我得到的会是一个能跑但不知道为什么这么跑的黑箱：参数一改就崩，崩了还分不清是物理算错了还是代码写错了。
